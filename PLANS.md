## Интеграция каналов продаж — замена МойСклад (YClients ↔ Тильда, потом Ozon)

Убираем МойСклад — наша интеграция сама становится «связочным звеном». Этапами: сначала Тильда,
потом Ozon. Отдельный проект `tilda-yclients-integracia-magazin` (свой Apps Script, свои ключи).
Стабильные факты — адреса, scriptId, deploy URL, ключ сопоставления, механизм обоих потоков,
грабли — в разделе «Интеграция Тильда ↔ YClients (магазин)» файла `PROJECT.md`. Здесь — только план.

- ✅ **Поток A (магазин → сайт: остатки + цены) — РАБОТАЕТ на автопилоте (25.07):** изменения
  по складу каждые 5 мин + полная сверка КАЖДЫЙ ЧАС (она подтягивает цены — их движение по складу
  не создаёт) + чистка журнала. Названия НЕ синхроним (в Тильде — свои продающие, в YClients —
  по прайсам поставщиков). Ключ = `_`+good_id (без дублей). Нагрузка минимальна.
- ✅ **Поток B (сайт → магазин: заказы) — РАБОТАЕТ, полный цикл пройден настоящим заказом
  с сайта (25.07, 22:34):** вебхук Тильды → списание в YClients одной операцией → подпись
  «Заказ из интернет-магазина El'Naturel Shop №<номер заявки>» и в списке, и в карточке →
  финоперация НЕ создаётся (выручку Ирина проводит сама) → сайт обновился сам. Удаления
  складских операций пятиминутка тоже замечает (сравнение списков, без лишних запросов).
- ⏭️ **Осталось:**
  • Обкатать пятиминутку на первых реальных онлайн-продажах.
  • ✅ **Признак канала для Блока B уже есть — отдельный поставщик НЕ нужен** (замечание Ирины
    25.07, снял свою же идею). Комментарий операции содержит слова «интернет-магазин» —
    именно по ним Блок B и разносит себестоимость по каналам (правило от 14.07). Дублировать
    это полем «поставщик» смысла нет.
  • **Отменённые заказы — ручной режим, автоматика пока НЕ нужна (решение Ирины 25.07).**
    Галка Тильды «отправлять только после оплаты» выключена осознанно: на сайте есть оплата
    при получении, иначе такие заказы к нам не пришли бы. Ирина обрабатывает КАЖДЫЙ заказ
    вручную (связывается с покупателем, договаривается об оплате), поэтому контроль есть
    по умолчанию. К автоматике (приём отмены → возврат) вернёмся, только если отмены станут
    частыми — сейчас не делать.
    ⚠️ **ВАЖНО — сказать Ирине при первом же отменённом заказе:** удаление заказа в ТИЛЬДЕ
    остаток в YClients НЕ возвращает (раньше, при МойСкладе, возвращало). Наша интеграция
    создаёт списание в YClients, и Тильда получает остаток ИЗ YClients абсолютным числом —
    то есть правка на стороне Тильды затрётся следующей синхронизацией. Возвращать остаток
    нужно в YClients: удалить складскую операцию «Продажа товара» по этому заказу — комментарий
    **«Заказ из интернет-магазина El'Naturel Shop №<номер>»**, где номер — номер ЗАЯВКИ Тильды,
    то есть сквозная нумерация Ирины (она включила эту передачу 25.07; своего счётчика не держим).
    Через ≤5 мин сайт обновится сам.
  • **Убрать/закрыть диагностику** после обкатки Потока B: `doGet` открыт наружу и гейтится
    захардкоженным секретом — через него можно перезаписать Script Properties, удалить документ,
    создать операцию. Удалить `setup`/`delDoc`/`testOp` или перенести секрет в Script Property.
  • ✅ **Новые товары — вопрос закрыт** (уточнение Ирины 25.07): «создавать новые» в Тильде
    ВКЛючено, карточка создаётся сама из фида (название и цена из YClients, External ID
    проставляется), Ирина дозаполняет категорию. Ручных действий и писем не нужно.
  • Связка с финансами (Блок B): онлайн-продажи попадут в кол-во товара «Без сотрудника — продажи»,
    выручка = 0 (её Ирина проводит статьёй) → свести, чтобы не задвоилось.
